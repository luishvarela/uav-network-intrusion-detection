This repository brings together two stages of a project on network traffic classification for attacks against **Unmanned Aerial Vehicles (UAVs / drones)**:

1. Training and evaluating deep learning models to classify normal traffic and identify attack classes.
2. Evaluating model robustness to adversarial perturbations.

## Projects

### [Neural network traffic classification](deep-learning-models/README.md)

Compares MLP, RNN, CNN, GRU, and LSTM architectures on binary and multiclass tasks. Includes data preparation, hyperparameter tuning, metrics, confusion matrices, and reproduction instructions.

### [Adversarial attack evaluation](adversarial-attacks/README.md)

Applies FGSM, PGD, and Gaussian noise to the models. It includes exploratory binary and multiclass adversarial-training pilots and a binary FedAvg baseline with simulated IID shards, along with results, figures, and evaluation limitations.

## How the stages fit together

The adversarial evaluation reuses the dataset, scalers, encoders, and baseline models generated by the classification project. To reproduce the main workflow, start with [`deep-learning-models/`](deep-learning-models/README.md): run hyperparameter tuning only if you want to refresh the saved parameters, then run the training notebook for each task you need. Next, use [`adversarial-attacks/`](adversarial-attacks/README.md) to evaluate FGSM/PGD, run an adversarial-training pilot, or test FedAvg with simulated clients. The CSV remains alongside the training notebooks; the adversarial project consumes those data and model artifacts and stores its own results.

Each stage keeps its current results in stable directories. A new run replaces those files rather than creating timestamped copies. The reference classification results are kept separate from the results using cleaned data.

## Which notebooks should I run?

**You do not need to run every notebook.** Run notebooks according to the results you need:

1. **Refresh hyperparameters (optional):** run `binary_tuning.ipynb` and/or `multiclass_tuning.ipynb` in `deep-learning-models/` only if you want to redo the search. Existing parameters are saved in `bayesian_tuning/`.
2. **Refresh the baseline models:** run `binary_training.ipynb` and/or `multiclass_training.ipynb` for the task(s) you need. These generate the model checkpoints and preprocessing artifacts used by later experiments.
3. **Run only the adversarial experiment you need:** `adversarial_attack_evaluation.ipynb` evaluates FGSM, PGD, and Gaussian noise; `adversarial_training_binary.ipynb` and `adversarial_training_multiclass.ipynb` are separate centralized pilots; and `fedavg_baseline.ipynb` / `fedavg_multiclass.ipynb` compare simulated FedAvg, FedProx, and SCAFFOLD experiments.

If you change or regenerate a baseline model, rerun only the downstream notebooks whose inputs depend on that model. If the baseline artifacts have not changed, there is no need to rerun the tuning or training notebooks just to run an adversarial experiment. The multiclass FedAvg notebook has no results recorded in the adversarial README yet, so run it only if you need that experiment's outputs. Execute each selected notebook's cells in order.
